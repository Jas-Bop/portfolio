## Popcorn

```python
# UESL 3.2 Popcorn - Extend the level sequence
level_stars = [6, 9, 12]
level_stars[1] = level_stars[1] + 3
level_stars.append(5)
print(level_stars)
print(len(level_stars))
```

Prediction: The second level starts at `9`, then increases by `3`, so it becomes `12`. Appending `5` adds a new fourth level. The list should print `[6, 12, 12, 5]`, and the length should print `4`.

Actual output:

```text
[6, 12, 12, 5]
4
```

AP index connection: Python index `1` selects the second level, so the matching College Board pseudocode index is `2`.

Changing the appended value from `5` to `8` would print `[6, 12, 12, 8]` and still have length `4`. Updating an existing element keeps the same length, but appending adds one new element.

## Homework

```python
# UESL 3.2 Homework - Grow your UESL game
level_stars = [12, 18, 10]

# Each element stores one level's collected stars, in level order.
level_stars[1] = level_stars[1] + 5
level_stars.append(7)

total_stars = 0
for stars in level_stars:
    total_stars = total_stars + stars

print(level_stars)
print(len(level_stars))
print(total_stars)
```

Prediction: Level two changes from `18` to `23`, and the new level with `7` stars becomes the fourth element. The collection should be `[12, 23, 10, 7]`, the level count should be `4`, and the total should be `52`.

Actual output:

```text
[12, 23, 10, 7]
4
52
```

## Tests

Test 1 - main game with four levels.

```python
level_stars = [12, 18, 10]

level_stars[1] = level_stars[1] + 5
level_stars.append(7)

total_stars = 0
for stars in level_stars:
    total_stars = total_stars + stars

print(len(level_stars))
print(total_stars)
```

Prediction: The level count should be `4`, and the total should be `52`.

Actual output:

```text
4
52
```

Result: The traversal works after the list grows because the `for` loop visits every current element.

Test 2 - empty project.

```python
level_stars = []

if len(level_stars) >= 2:
    level_stars[1] = level_stars[1] + 5

total_stars = 0
for stars in level_stars:
    total_stars = total_stars + stars

print(len(level_stars))
print(total_stars)
```

Prediction: The empty list has no second element, so the update is skipped. The level count should be `0`, and the total should be `0`.

Actual output:

```text
0
0
```

Result: This test starts fresh and avoids an invalid index. The same total-only traversal still works because looping over an empty list simply runs zero times.

Complexity explanation: A list avoids creating `level_one_stars`, `level_two_stars`, `level_three_stars`, and so on for every level. If the game had 100 levels, I could add, remove, or reorder entries in one collection while the traversal code for counting levels and totaling stars would stay the same.

## Design Thinking

Player/maker need: A UESL game maker needs to manage level scores in order without making the code harder every time a level is added.

Goal: My goal was to refactor the 3.1 prototype from separate level variables into one ordered list that can be updated, appended to, counted, and traversed.

Representation considered: I considered separate variables because they are readable for three levels, but a list is better because each element represents one level and the same loop can handle different lengths.

Prototype: I built `level_stars = [12, 18, 10]`, added `5` to the second level, appended `7` for a new level, and used a loop to calculate the total.

Test/revision: I tested the normal four-level game and an empty project. The empty project reminded me to check `len(level_stars) >= 2` before trying to update the second element.

Clear level labels should be shown in the game interface so players and makers do not need to understand list indices to know which level they are editing.
